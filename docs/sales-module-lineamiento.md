# Sales Module — Lineamiento (Unificar Sales + Navegación)

Referencia: `adaptio-unify-sales.md`. Este documento fija el lineamiento aplicado en el código.

---

## 1. Objetivo

- **Un solo módulo Sales** en el sidebar con 3 tabs: `[Quotes] [Proposals] [Orders]`.
- "Orders" dentro de Sales = Sales Orders (no una entrada separada en el sidebar).
- En **todas** las rutas `/sales/*` (listas y detalles) la barra superior muestra siempre los 3 tabs.

---

## 2. Sidebar

- **Una sola entrada:** "Sales" → href `/sales/quotes` (redirect a última ruta visitada en Sales si aplica).
- **Sin** entrada separada "Sales Orders".
- Submenú al hover (si aplica): Quotes, Proposals, Orders.
- "Sales" activo cuando `currentRoute.startsWith('/sales')`.

---

## 3. Navegación superior (tabs)

- En **todas** las páginas del módulo Sales se muestran los 3 tabs: **Quotes | Proposals | Orders**.
- Rutas donde debe verse:
  - `/sales/quotes`, `/sales/proposals`, `/sales/orders`
  - `/sales/quotes/:id`, `/sales/proposals/:id`, `/sales/orders/:id`
- Quién registra los tabs:
  - Listas: `SalesDirectory` (siempre registra "Sales" con los 3 tabs).
  - Detalle Quote: `QuoteDetail` (registra "Sales" con los 3 tabs).
  - Detalle Order: `SalesOrderDetail` (registra "Sales" con los 3 tabs).
  - Proposals: contenido dentro de `SalesDirectory` con `activeTab="proposals"`, ya tiene los 3 tabs.

---

## 3.1 Container y barra de búsqueda con filtros (igual en Quotes, Proposals, Orders)

- **Container:** página con `py-6 px-6`; header con título `text-xl font-semibold text-foreground mb-1` y subtítulo opcional.
- **Barra de búsqueda y filtros:** mismo formato en las tres listas (Quotes, Proposals, Orders):
  - Card: `bg-white border border-gray-200 py-6 px-6 rounded-lg` (o `rounded-t-lg` cuando el panel de filtros está abierto).
  - Fila: `flex items-center gap-3` → **Search** (flex-1, input `pl-9 pr-3 py-1`) + botón **Filters** (`px-2 py-1`, icono 14px; activo = `bg-blue-600 text-white`) + botón **Refresh** solo icono (`p-2`, icono 14px, sin texto; estilo secundario). No se muestra Refresh en el header de la página.
  - Panel de filtros (al abrir): `mt-4 pt-4 border-t border-gray-200`; sección "Status" con toggles y "Limpiar" si hay selección.
- Referencia de diseño: `.cursor/rules/design-system.mdc` y `.cursor/rules/directory-design-standards.mdc`.

---

## 4. Página Orders (lista)

- **SO number format:** `SO-YYYYMMDD-NNNNNN` (e.g. `SO-20260224-000100`). Generated by DB trigger; consecutive per **organization** per day (min 100). QT and PR numbers remain consecutive per **dealer** (app-side).
- **Header:** Misma estructura que Quotes y Proposals: `flex items-center justify-between mb-6`; bloque izquierdo con título `text-xl font-semibold text-foreground mb-1` y subtítulo `text-xs` + `var(--gray-500)`; bloque derecho con `flex items-center gap-3 ml-auto` (acciones pegadas al padding derecho; puede estar vacío). Sin Refresh en header; Refresh solo en la barra de filtros (icono).
- **Status tabs (nivel 2):** All | Draft | Open | On Hold | Completed | Closed | Cancelled.
- **Search bar con filtros:** mismo formato que Quotes y Proposals (ver 3.1): card py-6 px-6, Search + Filters + Refresh; panel expandible con filtro por Status y "Limpiar".
- **Tabla — columnas:**  
  SO # | Customer | [Dealer | Dealer ID si org] | Status | Payment | [Priority | Paid | Balance | MOs si no portal] | Date | Total | Actions
- **Dealer / Dealer ID:** solo visibles para usuarios org (internal). Dealer ID = primeros 8 caracteres del UUID.
- **Actions:** columna al final, pegada al padding derecho. **Dealer (portal):** solo Ver + Archivar (no puede borrar un SO). **Org (internal):** Ver + Eliminar. Refresh solo en la barra de búsqueda (icono, sin texto); no Refresh en el header.
- **MOs:** "—" si 0, "1 MO" / "N MOs" según count de `ManufacturingOrders` por `sales_order_id`.
- Fila clickeable → `/sales/orders/:id`.

---

## 4.1 Quotes y Proposals — Archivados

- **Archivar:** solo se puede archivar cuando el status es **cancelled**, **rejected** o **expired**. Ningún status activo (draft, sent, approved, converted, etc.) debe poder archivarse.
- **Tab "Archivados":** después del tab "Expired" (o "Cancelled" en Quotes) se muestra el tab **Archivados**. En ese tab solo se listan los registros archivados.
- **Restaurar:** en el tab Archivados, cada fila tiene acción **Restaurar** (icono RotateCcw); al confirmar se pone `archived = false` y el registro vuelve a la lista activa.
- **Base de datos:** tablas `Quotes` y `Proposals` tienen columna `archived` (boolean, default false). Las listas principales excluyen archivados salvo cuando el tab activo es "Archivados".

## 5. Limpieza de data corrupta (Tarea 4)

SOs de prueba con totales $0 o datos incoherentes. Ejecutar en Supabase SQL Editor (ajustar filtro si hace falta). **Schema real:** tabla `SalesOrders`, columna `sales_order_no` (no `so_number`).

```sql
-- Eliminar payments de los SOs a limpiar (ej. por patrón en sales_order_no)
DELETE FROM "Payments" WHERE sales_order_id IN (
  SELECT id FROM "SalesOrders" WHERE sales_order_no LIKE 'SO-QT-%'
);

-- Timeline
DELETE FROM "ActivityTimeline" WHERE entity_type = 'sales_order' AND entity_id IN (
  SELECT id FROM "SalesOrders" WHERE sales_order_no LIKE 'SO-QT-%'
);

-- MOs asociados
DELETE FROM "ManufacturingOrders" WHERE sales_order_id IN (
  SELECT id FROM "SalesOrders" WHERE sales_order_no LIKE 'SO-QT-%'
);

-- Líneas del SO
DELETE FROM "SaleOrderLines" WHERE sales_order_id IN (
  SELECT id FROM "SalesOrders" WHERE sales_order_no LIKE 'SO-QT-%'
);

-- Por último los SOs
DELETE FROM "SalesOrders" WHERE sales_order_no LIKE 'SO-QT-%';

-- Opcional: resetear Quote convertido para re-testear flujo
-- UPDATE "Quotes" SET status = 'pending_confirmation', converted_at = NULL
-- WHERE status = 'converted';
```

**Hacer backup** si hay duda. Adaptar el filtro `sales_order_no LIKE '...'` al criterio real.
